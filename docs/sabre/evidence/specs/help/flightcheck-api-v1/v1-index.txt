Overview

What is it?

Sabre Flight Check is a multi-source API that allows you to recreate valid offers for checkout from cached itineraries.

A flight check is a fully live transaction that converts cached itineraries into bookable offers through the Sabre Order Management system. It's a mandatory step in the workflow, used to revalidate offers when there's a good chance to convert an itinerary into a booking.

The API supports the following features:

Validates whether the offer exists for the current price. Is the itinerary still available?

Validates the price and availability in the specified booking class. Can it be offered in the provided booking code?

Validates the price and availability in an alternative booking class. Is there an alternative pricing solution for the offer in the same cabin?

Why use it?

Improves bookability: Once an offer is selected for purchase, the API ensures that the offer still exists, and it provides the necessary details to continue ordering.

Addresses operational needs: Increases customer satisfaction by closing the loop between cache-based searches and order creation.

Boosts upsells and conversion: Provides fare retailing capabilities that enable seamless conversion and upselling opportunities across content sources.

Normalized workflow: Supports real-time offer validation and recreation across multiple sources.

How it works

v1/offers/flightCheck

The Sabre Flight Check API is available via JSON REST technology. It lets you revalidate the price and availability of an itinerary offer without decrementing or holding airline inventory.

Offer revalidation prevents booking failures. It's a fully live transaction, limited to a single itinerary.

 |

This API will replace the Revalidate Itinerary API and the Offer Price API, integrating their capabilities into one single service.
 |

The API supports the following functionalities:

ATPCO (payload) and NDC (offerItemID)

cabin preferences for pricing

offer inclusions (returns Baggage and Flexibility)

fare revalidation with account codes

fare revalidation by offer inclusions (such as hasFreeBaggage and hasFreeRefund)

Provides alternatives if the current fare or booking code isn't available.

Returns the details necessary to create an order, including offerItemID and marriage group indicators.

Supports multiple-branded fares (ATPCO only in the first phase).

Returns carbon emissions.

A successful call includes itinerary details in the request, along with other mandatory data such as the passenger type code and pseudoCityCode. Depending on the offer type, the API performs a flight check in one of the two ways outlined below:

Based on payload: Revalidates fares and availability for single offers using payload itinerary details as input. Applied for traditional EDIFACT offers.

Based on offerItemID: Validates the price of an offer using a valid offerItemID. Applied for NDC offers.

After you send your request, the API returns the following information:

A normalized offer price response with full offer details (marriage group indicators, offerItemID) and all data necessary to proceed with the order using Sabre Order or the Booking Management API.

Response flags that indicate if the API matched the offer or if an alternative offer was provided (EDIFACT).

Messages from the airline informing about both successes and errors (NDC).

How to use

Authentication

You must provide an authentication token to all endpoints within the Sabre Flight Check API. Tokens can be obtained from the OAuth Token Create API.

v1/offers/flightCheck/

To retrieve offers matching desired parameters, send a POST request to the v1/offers/flightCheck/ endpoint.
