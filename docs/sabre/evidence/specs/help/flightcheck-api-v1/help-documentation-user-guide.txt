Sabre Flight Check API User Guide

Introduction

The Sabre Flight Check API allows you to complete fully live transactions that convert cached itineraries into bookable offers. It's a mandatory step in the workflow, limited to a single itinerary. This API is especially useful when there's a good chance that cached itineraries can be converted into bookings, meaning the traveler has made their final decision.

Key Features

Validation based on payload

The API can revalidate fares and availability for single offers using payload itinerary details as input.
Offer revalidation takes place when the source is known, and the current price and availability need to be checked before the required details are used to create an order.

For ATPCO content, this means the API completes the following steps:

Revalidates an itinerary offer without decrementing or holding airline inventory. This was previously orchestrated using the Revalidate Itinerary API.

Validates the availability of the itinerary (RBD).

Returns an offer price response with full offer details (marriage group indicators) to proceed with the order using Sabre Order or the Booking Management API.

Returns response flags that indicate if the API matched the offer or if an alternative offer was provided.

Validation based on offerItemID

The API may validate the price of an offer using a valid offerItemID.

For NDC content, this means the API completes the following steps:

Verifies the price of an itinerary offer (can be orchestrated using the Offer Price flow):

Validates the request by checking its consistency with the offer.

Updates passenger information from the offer with the data provided in the request.

Builds and sends a request to the airline via the IATA's NDC Offer/Price API.

Creates and stores offers based on the response from the IATA's NDC Offer/Price API. These offers have their time-to-live specified in the response.

Creates warning messages based on the airline's response or configuration (e.g., messages informing about a possible price increase if the form of payment wasn't provided).

Builds and returns an offer price response with offer details.

Returns a normalized offer price response with offer details and data necessary for subsequent order creation using the Orders/Create API (Order Management API).

Returns messages from the airline informing about both successes and errors.

Other validation scenarios

If both types of input are provided in the request, that is, offeritemID (NDC content) and payload data (ATPCO content), the API proceeds as follows:

Gives precedence to the payload input.

Ignores the offeritemID.

Processes the payload input.

Displays an error message (e.g.: “offeritemID not supported”).

If only one type of input is provided in the request, yet additional requested attributes are not supported, the API behaves as follows:

Ignores the unsupported features for the path.

Processes as normal.

Passenger information

The API accepts input within the travelers array. This allows you to provide passenger information, including the frequent-flyer number, as shown in the code snippet below.

"travelers": [
	{
		"passengerTypeCode": "ADT",
		"givenName": "John",
		"surname": "Smith",
		"loyaltyPrograms": [
			{
				"supplierCode": "AA",
				"programNumber": "11233"
			}
		]
	},
	{
		"passengerTypeCode": "CNN"
	}
],

Support for the form of payment (NDC) is optional, which may affect the price.
 |

Processing-related features

To enable special features of offer generation, use processingOptions in your request:

pseudoCityCode: The Point of Sale identifier. Applicable to ATPCO.

configurationId: Triggers the desired shopping profile and service.

"processingOptions": {
	"pseudoCityCode": "27M7",
	"configurationId": "abc12345",
}

Retailing and fare parameters

To price the desired fare for an offer to revalidate, the Flight Check API allows you to provide already existing Flight Shop fares and retailing parameters:

Supports price by cabin preferences, currency code, forced pax types, and validation.

Returns offer inclusion decorations (Baggage, FlexibilityRule, carbon emissions).

Revalidates the fare for specified account codes and offer inclusions (hasFreeBaggage, hasFreeRefund).

Returns additional upsells (for ATPCO and LCC in the first phase of development).

Full offer details

The API returns the following offer data in the response:

normalized offer details (price)

detailed information about the offer, price components, and included services

full offer fare details (fareComponents, fareBasis codes, brand ID, etc.)

baggage information

refund and change information

tax breakdown

ticketing endorsements

 |

Support for OB Fees is planned for the next development phase.
 |

Response flags

For EDIFACT (ATPCO) offers, the API returns the following response flags for price and availability validation:

bookingClassCodeValidation set to matched if the itinerary can be offered in the provided booking code (RBD).

bookingClassCodeValidation set to same_cabin if there's an alternative pricing solution for the offer in the same cabin.

bookingClassCodeValidation set to none if the offer couldn't be validated. No offer is returned.

Messages from NDC airline

The API returns messages from airlines from NDC Offer Price. The snippet below shows how such a message can be structured in the response:

"itinerary": [
   {
   "messages": [
      {
       "type", "WARNING",
        "message": "Invalid form of payment reference"
      }
   ]
  }
 ],

 |

The response will include all messages returned from the airline, for both successful and error results.
 |

Booking & Servicing Workflow

Sabre Cache: A new multi-source content-agnostic GCP-based cache. Capable of storing content from any provider and exposing it to shopping APIs such as Sabre Flight Shop.

Flight Search: An API designed to inspire travel. Enables you to make open origin or destination and date searches across multi-source flight content from cache, including public cache, pre-charged, and API subscribers' private content.

Flight Refresh: An API for high-volume itinerary validation workflows. Empowers cache-based platforms to validate multiple offers simultaneously against Sabre inventory. Checks the availability of offers returned from client-side caches.

Flight Shop: An API that retrieves the best flight offers for travelers across different air sources, data providers and distribution models. Supports Sabre EDIFACT, NDC and LCC content, as well as pre-computed offers stored in the Sabre Cache.

Flight Shop Lite: A lite version of the Sabre Flight Shop API. Finds the best offers across different content sources. Has fewer capabilities than the full Flight Shop API and is therefore available at a lower price point.

Flight Check: Once an offer has been selected for purchase, this API revalidates the price, checks availability, and provides upsell capabilities of the offer across content sources. It allows you to recreate valid offers from cached itineraries for checkout.

Flight Policy Display: An API that allows you to request specific fare rule information and have it returned in a structured format. It's a standalone API that can be used after pricing, shopping, ticketing, or even after the ticket is used or exchanged.

Flight Reshop: A next-generation, multi-source API that enables seamless exchange shopping across a wide range of air content, including multi-GDS tickets and multi-source offers.

Order Management API: A powerful, orchestrated API designed to streamline and unify the booking and post-booking processes across multiple travel content sources (air, lodging). Provides a normalized, Sabre-agnostic interface that abstracts the complexity of diverse content providers, enabling seamless orchestration of order-related business services.
